# القوالب

خمس مجموعات، كلٌّ تُنسخ إلى موضعها في شجرة `docs/` للمشروع الجديد. القالب يحمل البنية والقواعد والأعمدة ومفردات الحالة؛ ولا يحمل محتوى.

| المجموعة | تُنسخ إلى | ما فيها |
|---|---|---|
| `discovery/` | `docs/discovery/` (قبل Phase 0) | **الدراسة التأسيسية** لمشروع يبدأ من ملفات خام (عطاء · عرض · عقد · SRS · شاشات): موجّه الاكتشاف والمصالحة وتقييم الجاهزية للمواصفات، بجرد مصادر مُعرَّف وسجلّي تعارضات وفجوات وأسئلة بخيارات وتوصية |
| `module/` | `docs/01-modules/<module>/` | حزمة الموديول: 9 وثائق Phase 0 (منها مجلد `screens/`) و5 وثائق هندسية، مع `README.md` يشرح ترتيب إنتاجها وأي بوابة تراجع كلًّا منها |
| `quality-gates/` | `docs/99-quality/` | 14 بوابة جودة توثيقية: قوائم تحقق وأسباب رفض ومستويات خطورة وقالب تقرير. تُنفَّذ كمراجعة ذاتية قبل عرض أي مخرج على مالك المنتج |
| `implementation/` | `docs/03-development/implementation/` | منظومة التخطيط التنفيذي: الخطة الرئيسية، خطط الموديولات، المتتبع (مصدر حالة التنفيذ الوحيد)، تعريف الإنجاز متعدد المستويات، الاعتماديات والموجات، المخاطر وبوابات القرار |
| `programmes/` | `docs/03-development/implementation/<programme>/` أو `docs/99-quality/` | **البرامج متعددة الدورات** التي تعبر الشرائح: مراجعة جاهزية مرحلة قبل البرمجة · برنامج تقرير الجودة (أحكام المالك ⟵ دورات ⟵ فحص شامل ⟵ توصيات) · برنامج اللغة الثانية. لكلٍّ بنيته وترقيمه المؤقت وقاعدة إغلاقه |

## قواعد مشتركة

1. **القالب لا يُعدَّل داخل المشروع.** إن احتاج المشروع عمودًا أو قسمًا جديدًا يُرفع إلى الإطار بإصدار جديد، كي لا تتباعد المشاريع.
2. **كل جدول يحمل عمود المعرّف أولًا** وعمود المصدر الذي يُردّ إليه، وعمود الحالة بمفرداتها المحددة في القالب.
3. **الحالة التشغيلية تُكتب في المتتبع وحده.** أي ملف آخر يُحيل إليه ولا ينسخ منه.
4. **`{{...}}` تُستبدل كلها عند النسخ.** أمر الفحص: `grep -rn '{{' docs/`.
