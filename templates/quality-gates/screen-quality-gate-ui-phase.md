# بوابة جودة حزمة الشاشات — Screen Quality Gate (مرحلة الواجهة)

**الإصدار:** 1.0 — مرحلة تحليل الواجهات وبناء الواجهة الأولية  
**المسار القياسي:** `docs/99-quality/screen-quality-gate-ui-phase.md`  
**النطاق:** مرحلة الواجهة فقط. لا يطلب هذا الملف API أو قاعدة بيانات أو Backend ما لم يطلبها مالك المنتج صراحة.

---

## الهدف

التحقق من اتساق `screen-inventory.md` و`permission-matrix.md` ومواصفات الشاشات (`screens/`) وجاهزيتها لتسليمها إلى مرحلة بناء الواجهة بإطار الواجهة ومكتبة المكوّنات المعتمدَين في المشروع.

## المراجع

- `requirements.md`
- `user-flows.md`
- `screen-inventory.md`
- `permission-matrix.md`
- مواصفات الشاشات (`screens/`)
- القرارات والمراجع العالمية ذات الصلة
- المكونات والتخطيطات الموجودة في مشروع الواجهة عند توفره

## قائمة التحقق

### الحصر
- [ ] كل شاشة مرتبطة بهدف مستخدم أو تدفق أو حالة نظام.
- [ ] لا توجد شاشات مكررة أو وظائف مشتركة معاد إنشاؤها.
- [ ] الأولوية والمرحلة والدور المستهدف محددة.

### الصلاحيات
- [ ] كل إجراء حساس له سلوك صلاحية موثق.
- [ ] سلوك منع الصلاحية محدد: إخفاء أو تعطيل أو قراءة فقط أو رفض وصول.
- [ ] لا يتم افتراض صلاحيات إدارية عامة بلا قرار.

### المواصفات
- [ ] لكل شاشة معرف وغرض ونقاط دخول وخروج وRoute مقترح.
- [ ] الحقول، الإجراءات، الحوارات، التحويلات، والتحقق موثقة.
- [ ] حالات Initial وLoading وEmpty وError وSuccess وPermission Denied مغطاة حسب الانطباق.
- [ ] بيانات العرض الوهمية أو المحلية واضحة.
- [ ] اختيار Layout أو Component من مكتبة المكوّنات المعتمدة مبني على ما هو موجود أو معلّم `PROPOSED`.
- [ ] التجاوب والرسائل وحالات التعطيل موثقة عند الحاجة.
- [ ] لا تشترط المواصفة API أو قاعدة بيانات أو Backend في المرحلة الحالية.

## تقرير المراجعة

لكل ملاحظة: المعرف، المستوى، الشاشة أو القسم، الوصف، الأثر، التوصية، المرجع، والحالة.

## الاعتماد

لا تصبح حزمة الشاشات جاهزة للتنفيذ إذا وجدت مشكلة `Critical` أو `High`، أو إذا كان هناك قرار مفتوح يمنع تنفيذ شاشة حرجة.

```text
STATUS = APPROVED
```
