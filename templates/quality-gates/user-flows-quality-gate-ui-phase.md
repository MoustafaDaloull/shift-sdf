# بوابة جودة تدفقات المستخدم — User Flows Quality Gate (مرحلة الواجهة)

**الإصدار:** 1.0 — مرحلة تحليل الواجهات وبناء الواجهة الأولية  
**المسار القياسي:** `docs/99-quality/user-flows-quality-gate-ui-phase.md`  
**النطاق:** مرحلة الواجهة فقط. لا يطلب هذا الملف API أو قاعدة بيانات أو Backend ما لم يطلبها مالك المنتج صراحة.

---

## الهدف

التحقق من أن `user-flows.md` يصف المسارات اللازمة للمستخدم داخل الواجهة، بما فيها القرارات والاستثناءات وحالات الفشل ذات الأثر المرئي.

## المراجع

- `requirements.md`
- القرارات المعتمدة
- قواعد السلوك العالمية ذات الأثر على الواجهة
- ملكية الوظائف المشتركة

## قائمة التحقق

- [ ] لكل تدفق هدف واضح ودور أو جهة منفذة ونقطة بداية ونهاية.
- [ ] الخطوات مرتبة ولا تفترض بيانات أو صلاحيات غير معرفة.
- [ ] نقاط القرار مرتبطة بمتطلب أو قرار أو قاعدة سلوك معتمدة.
- [ ] الحالات البديلة والاستثناءات التي تغير واجهة المستخدم مغطاة.
- [ ] مسارات رفض الصلاحية والإلغاء وإعادة المحاولة وتغير حالة السجل مغطاة عند الحاجة.
- [ ] لا يعيد التدفق إنشاء OTP أو الدفع أو الإشعارات أو غيرها من الوظائف المشتركة المملوكة لموديول آخر.
- [ ] يمكن اشتقاق الشاشات والحالات المطلوبة من التدفق دون افتراض جوهري.
- [ ] لا يتضمن التدفق API أو Backend خارج نطاق المرحلة.

## الاعتماد

يمنع الاعتماد وجود تدفق رئيسي ناقص، أو قرار بلا مصدر، أو مسار فشل جوهري غير مغطى.
