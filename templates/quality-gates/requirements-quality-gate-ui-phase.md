# بوابة جودة المتطلبات — Requirements Quality Gate (مرحلة الواجهة)

**الإصدار:** 1.0 — مرحلة تحليل الواجهات وبناء الواجهة الأولية  
**المسار القياسي:** `docs/99-quality/requirements-quality-gate-ui-phase.md`  
**النطاق:** مرحلة الواجهة فقط. لا يطلب هذا الملف API أو قاعدة بيانات أو Backend ما لم يطلبها مالك المنتج صراحة.

---

## الهدف

التحقق من أن `requirements.md` يحدد نطاق الموديول والمتطلبات والأدوار والاعتماديات اللازمة للوصول إلى واجهات المستخدم، دون الانزلاق إلى تصميم API أو قاعدة بيانات.

## المراجع

- `module-registry.md`
- BRD
- `project-decisions.md`
- `glossary.md`
- `business-rules-global.md` عند وجود أثر على الواجهة

## قائمة التحقق

- [ ] هوية الموديول والمرحلة وحدود الملكية مطابقة لسجل الموديولات.
- [ ] نطاق المرحلة ينتهي عند تسليم واجهات المستخدم ولا يتضمن Backend أو API دون طلب.
- [ ] جميع الأدوار المتأثرة محددة.
- [ ] المتطلبات الوظيفية ذات الأثر على الواجهة قابلة للتحويل إلى تدفقات وشاشات.
- [ ] الوظائف المشتركة المستهلكة ومالكوها موثقة.
- [ ] القرارات المؤثرة على الظهور، الإجراء، أو الصلاحيات محددة أو مسجلة `OPEN`.
- [ ] لا توجد تفاصيل شاشات أو API أو بيانات تفصيلية خارج نطاق الملف.
- [ ] كل متطلب قابل للتتبع لمصدر أو قرار.

## تقرير المراجعة

لكل ملاحظة: المعرف، المستوى، القسم المتأثر، الوصف، الأثر، التوصية، والمرجع.

## الاعتماد

لا تعتمد الوثيقة إذا كان هناك `Critical` أو `High` مفتوح، أو قرار مفتوح يمنع فهم واجهة أساسية.

```text
STATUS = APPROVED
```
