# بوابة جودة تنفيذ الواجهة — UI Implementation Quality Gate

**الإصدار:** 1.0 — مرحلة تحليل الواجهات وبناء الواجهة الأولية (من النموذج الثابت إلى الواجهة المنفَّذة)  
**المسار القياسي:** `docs/99-quality/ui-implementation-quality-gate.md`  
**النطاق:** مرحلة الواجهة فقط. لا يطلب هذا الملف API أو قاعدة بيانات أو Backend ما لم يطلبها مالك المنتج صراحة.

> **تعميم:** كانت هذه البوابة في المشروع المرجعي مكتوبةً لإطار واجهة ومكتبة مكوّنات بعينهما. القواعد نفسها تنطبق على أي إطار واجهة ومكتبة مكوّنات أو قالب يعتمدهما المشروع؛ فحيث يرد «إطار الواجهة المعتمد» أو «مكتبة المكوّنات المعتمدة» يُقرأ ما قرّره المشروع في سجل قراراته.

---

## الهدف

التحقق من أن شاشات الواجهة المنفذة تتبع مواصفات الشاشات، وتستخدم إطار الواجهة ومكتبة المكوّنات المعتمدَين وبنية المشروع القائمة بصورة صحيحة، وتبقى ضمن نطاق الواجهة فقط.

## المدخلات

- مواصفات الشاشات (`screens/`)
- `permission-matrix.md`
- الملفات المنفذة في مشروع الواجهة
- `package.json` والـ scripts المتاحة
- Layouts وComponents وRouter ومكتبة المكوّنات الموجودة فعليًا

## قائمة التحقق

### الالتزام بالمشروع
- [ ] تم فحص مشروع الواجهة ومكتبة المكوّنات المعتمدة قبل التنفيذ.
- [ ] تم استخدام الهيكل الحالي للمجلدات والمسارات والمكونات.
- [ ] لم يتم إنشاء مشروع واجهة بديل أو Layout بديل.
- [ ] لم يتم تغيير إصدار إطار الواجهة أو مكتبة المكوّنات أو Dependencies دون موافقة.

### التوافق مع المواصفات
- [ ] كل شاشة منفذة مرتبطة بمعرف `SCR-...`.
- [ ] Route والتنقل والإجراءات توافق المواصفات.
- [ ] الصلاحيات المرئية وحالات التعطيل توافق `permission-matrix.md`.
- [ ] حالات Loading وEmpty وError وSuccess وPermission Denied موجودة عند انطباقها.
- [ ] الحقول والتحقق والرسائل وحوارات التأكيد مطبقة كما هو موثق.

### مكتبة المكوّنات والجودة البصرية
- [ ] تم استخدام Components وLayouts وUtilities الموجودة في مكتبة المكوّنات المعتمدة أولًا.
- [ ] لا يوجد CSS مخصص غير ضروري عندما تتوفر أداة مناسبة في المكتبة المعتمدة.
- [ ] التجاوب متسق مع النمط القائم في المشروع.
- [ ] البيانات التجريبية واضحة وواقعية ولا تحتوي نصوصًا افتراضية غير مناسبة للعرض.

### حدود المرحلة
- [ ] لا توجد طلبات API حقيقية أو تكاملات أو Backend.
- [ ] البيانات الوهمية أو الحالة المحلية لا توحي بأنها تكامل فعلي.
- [ ] لا توجد قرارات بيانات أو أمان خادمي مخترعة.

### التحقق التقني
- [ ] تم تشغيل أمر تحقق أو بناء متاح من `package.json`.
- [ ] لا توجد أخطاء بناء أو مسارات مكسورة أو Imports غير مستخدمة مؤثرة.
- [ ] لا توجد أخطاء ظاهرة تمنع استعراض الشاشة.

## تقرير المراجعة

لكل ملاحظة: المعرف، المستوى، الملف/الشاشة، الوصف، الأثر، التوصية، مرجع المواصفة، والحالة.

## الاعتماد

لا يعتمد التنفيذ إذا كان هناك `Critical` أو `High` مفتوح، أو إذا كان البناء المتاح يفشل بسبب التغييرات المنفذة.
