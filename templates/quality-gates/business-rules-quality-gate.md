# بوابة جودة قواعد العمل — Business Rules Quality Gate

**الإصدار:** 1.0  
**المسار القياسي:** `docs/99-quality/business-rules-quality-gate.md`  
**الحالة:** مرجع إلزامي  
**النطاق:** جميع موديولات {{PROJECT_NAME}} ما لم يعتمد مالك المنتج استثناءً صريحًا.

---

## 1. الغرض

تضمن هذه البوابة أن `business-rules.md` يترجم القرارات التجارية والتشغيلية إلى قواعد دقيقة وقابلة للتنفيذ والاختبار، مع تغطية الحالات والصلاحيات والمال والملكية والظهور والاستثناءات.

---

## 2. متى تُنفذ؟

- بعد إعداد أو تعديل `business-rules.md`.
- قبل اعتماد تدفقات المستخدم أو API أو منطق Backend يعتمد على القواعد.
- عند تعديل قرار مالي أو تشغيلي أو قانوني أو متعلق بالصلاحيات.

---

## 3. المراجع والمدخلات الإلزامية

- `requirements.md`
- `module-registry.md`
- `project-decisions.md`
- `business-rules-global.md`
- `brd.md`
- `الوثائق التشغيلية المتخصصة ومراجع الموديولات المالكة`

لا تُنشئ افتراضًا بدل مرجع مفقود. سجّل المرجع المفقود أو القرار الناقص كـ `OPEN`، واعتبره عائقًا إذا كان يؤثر في المال أو الصلاحيات أو الملكية أو الحالة أو الخصوصية أو الالتزام القانوني.

---

## 4. بروتوكول المراجعة الإلزامي

1. اربط كل Rule بمتطلب أو قرار مصدر.
2. اختبر كل قاعدة على النجاح والفشل والحالات الطرفية.
3. افصل بين Rule وValidation وPolicy وState Transition.
4. لا تعدل أثناء المراجعة الأولى.
5. أصلح Critical وHigh ثم أعد الاختبار والمراجعة.

---

## 5. قائمة التحقق

### الهوية والتتبع

- [ ] كل قاعدة تحمل معرفًا مثل `BR-[MODULE]-###`.
- [ ] لكل قاعدة مصدر أو قرار معتمد.
- [ ] القاعدة المشتركة تشير إلى موديول مالكها ولا تُكرر.
- [ ] المتطلبات والتدفقات والشاشات المتأثرة محددة.
- [ ] المصطلحات متوافقة مع `glossary.md`.

### دقة المنطق والحالات

- [ ] شرط التطبيق والفعل والنتيجة والاستثناء محددة.
- [ ] لا توجد كلمات غامضة مثل عند الحاجة أو مناسب دون معيار.
- [ ] ترتيب الأولوية بين القواعد المتعارضة موثق عند الحاجة.
- [ ] كل انتقال حالة يحدد المصدر والوجهة والشرط والجهة المخولة.
- [ ] الإلغاء والرفض والانتهاء والتعليق والاستئناف مغطاة عند الانطباق.

### الصلاحيات والملكية والظهور

- [ ] كل إجراء حساس يحدد من يملكه ومن يراه ومن ينفذه.
- [ ] قواعد الرؤية والتحرير والحذف والاعتماد متسقة مع الصلاحيات.
- [ ] تغير الملكية أو الوصول أو الظهور العام موثق.
- [ ] لا توجد صلاحية إدارية شاملة مفترضة دون قرار صريح.

### المال والاستثناءات والتدقيق

- [ ] المبالغ والعملة والرسوم والعمولات والعربون والتأمين لها مصدر ومالك.
- [ ] الاحتساب والتقريب والاستحقاق والاسترداد أو المصادرة محددة.
- [ ] الفشل الجزئي وتكرار الدفع وانتهاء المهلة مغطاة عند الانطباق.
- [ ] الاستثناءات والتدخل التشغيلي اليدوي يحددان الجهة والأثر.
- [ ] عمليات Audit Log الحساسة محددة أو محالة لموديول المالك.

---

## 6. أسباب الرفض أو الإيقاف

- قاعدة مالية أو قانونية أو صلاحية حساسة بلا قرار.
- تضارب بين قاعدتين دون أولوية.
- انتقال حالة بلا شرط أو جهة مخولة.
- قاعدة تتجاوز موديول المالك أو لا يمكن اختبارها.
- استثناء تشغيلي أساسي غير موثق.

---

## 7. تصنيف الملاحظات

| المستوى | المعنى | أثره على الاعتماد |
|---|---|---|
| Critical | خطأ في النطاق أو المال أو الأمان أو الصلاحيات أو القانون أو حالة السجل | يمنع الاعتماد |
| High | نقص أو تعارض قد يسبب تنفيذًا خاطئًا أو إعادة عمل كبيرة | يمنع الاعتماد |
| Medium | فجوة مهمة تحتاج إصلاحًا أو موافقة صريحة | لا يعتمد تلقائيًا |
| Low | تحسين محدود في الوضوح أو الصياغة أو التنظيم | يمكن تأجيله |

---

## 8. قالب تقرير المراجعة

```markdown
# Quality Review — [MODULE CODE]

**الملف المراجع:** [المسار]  
**المراجع المستخدمة:** [قائمة]  
**حالة المراجعة:** PASS / CONDITIONAL PASS / FAIL

## ملخص الملاحظات
| Severity | Count |
|---|---:|
| Critical | 0 |
| High | 0 |
| Medium | 0 |
| Low | 0 |

## قابلية التتبع
| Rule ID | Source / Decision | Affected Requirement | Flow / Screen / API | Result |
|---|---|---|---|---|

## Findings

### QG-[MODULE]-001
- **Severity:** Critical / High / Medium / Low
- **العنصر المتأثر:** [المعرف أو القسم]
- **الوصف:** [المشكلة بدقة]
- **الأثر:** [الأثر التشغيلي أو الفني أو القانوني]
- **التوصية:** [الإجراء المطلوب]
- **المرجع:** [Requirement / Rule / Flow / Decision / File]
- **الحالة:** Open / Resolved / Accepted Risk
```

---

## 9. معايير الاعتماد النهائي

- عدد `Critical = 0` و`High = 0`.
- كل قاعدة مؤثرة لها مصدر ونتيجة قابلة للاختبار.
- القواعد الحساسة للحالة والصلاحيات والمال والملكية والاستثناءات مكتملة.
- لا يوجد تعارض مع المتطلبات أو المراجع العالمية.

لا تعتبر الوثيقة مكتملة أو جاهزة للمخرج التالي إلا بعد إعادة المراجعة عقب الإصلاح.

استخدم النتيجة النهائية فقط عند تحقق الشروط:

```text
STATUS = APPROVED
```

وفي غير ذلك استخدم الحالة المناسبة:

```text
STATUS = BLOCKED
STATUS = NEEDS_REVISION
STATUS = CONDITIONAL_REVIEW
```
