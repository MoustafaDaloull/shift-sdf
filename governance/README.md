# طبقة الحوكمة

هذه الطبقة هي ما يجعل الوكيل البرمجي منفّذًا منضبطًا لا مُخترِعًا. تحتوي ملفات التعليمات الثلاثة التي تُثبَّت في جذر مشروع جديد، وقالب حالة المشروع، وقوالب سجل القرارات وطلبات التغيير ومنظومة المعرّفات.

| الملف | يُثبَّت في المشروع باسم | يحكم |
|---|---|---|
| `phase0-instructions.md` | `CLAUDE-PHASE0.md` | التحليل الوظيفي ومواصفات الشاشات. يُمنع كتابة الكود في هذه المرحلة |
| `engineering-instructions.md` | `CLAUDE-ENGINEERING.md` | الحزمة الهندسية: نموذج البيانات، عقود API، قصص المستخدم، السيناريوهات، التتبع |
| `execution-instructions.md` | `CLAUDE.md` | كتابة الكود واختباره وتشغيله. الملف الوحيد المُحمَّل تلقائيًا |
| `project-baseline-template.md` | `PROJECT-BASELINE.md` | حالة المشروع والمرحلة والحواجب وسلّم الحقيقة وبوابات القرار البشري |
| `decisions/` | `docs/00-product/` | سجل القرارات وفهارسه الستة، قالب طلب التغيير، قالب «قرار مطلوب»، منظومة المعرّفات |

## قواعد تخصّ هذه الطبقة

1. **ملف واحد نشط في كل مرحلة.** الملفات الثلاثة لا تتعارض لأن كلًّا يحكم نوع مخرجه. ما ورد في ملف Phase 0 من منع كتابة الكود يخصّ مخرجات Phase 0 ولا يسري على مرحلة التنفيذ.
2. **ملفات الحوكمة محميّة من الوكيل.** لا يُعدّلها إلا بتوجيه صريح من مالك المنتج، وكل تعديل يُسجَّل في جدول الإصدارات داخل الملف مع القرار الذي أوجبه.
3. **التعديل يتبعه تدقيق.** بعد كل قرار يغيّر قاعدة، يُدقَّق الملف كاملًا كي لا تبقى جملة تقول خلاف الجدول الذي تحتها (`lessons/README.md L-024`).
4. **المستوى الخفيف يدمج لا يحذف.** في المستوى الخفيف يُدمج محتوى الملفات الثلاثة في `CLAUDE.md` واحد، لكن قواعد كل مرحلة تبقى وتُعلَّم بمرحلتها.
5. **`{{...}}` تُستبدل كلها قبل أول جلسة.** أمر الفحص: `grep -rn '{{' CLAUDE*.md PROJECT-BASELINE.md`.
