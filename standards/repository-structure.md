# معيار بنية المستودع — Repository Structure Standard

> **الغرض:** تحويل مبدأ **الموديول ككيان ملكية** (`EP-MOD-001`) من مبدأ مجرّد إلى **بنية مجلدات ملزمة** تجعل خرق حدود الموديول ظاهرًا في مراجعة الكود بدل أن يكون مخفيًا فيه.
>
> **ما لا يحدده هذا المستند:** أسلوب كتابة الكود (`coding-standards.md`) · خطوط التشغيل الآلي (`automation-strategy.md`) · تفاصيل النشر السحابي.
>
> القواعد المرتبطة بحزمة تقنية بعينها تُطبَّق عبر ملف تعريف الحزمة `profiles/<name>/`؛ الافتراضي `laravel-react`.

---

## 1. المبدأ الحاكم

`EP-ARCH-003` يشترط أن يكون كل موديول **قابلًا للفصل لاحقًا كخدمة مستقلة دون إعادة بناء كاملة**. هذا الشرط لا يتحقق بالنية — يتحقق بالبنية.

**القاعدة المركزية:**

```
كل ما يملكه الموديول يقع داخل مجلده.
كل ما يستهلكه من غيره يمر عبر عقد مُصرَّح به.
لا استثناء ثالث.
```

**اختبار القبول العملي:** لو حُذف مجلد موديول بالكامل، يجب أن تكون كل الأعطال الناتجة **أخطاء استيراد عقود صريحة** — لا استعلامات صامتة تعيد نتائج فارغة.

## 2. البنية على مستوى الجذر

```text
{{project}}/
├── backend/                 # Laravel — يُركَّب على /var/www/html في الحاوية
├── frontend/                # React + TS + Vite — يُركَّب على /app
├── admin-ui/                # نموذج بوابة الإدارة الثابت (HTML) — مرجع تصميمي
├── docker/                  # تعريفات الحاويات والبيئات
├── docs/                    # التوثيق — مصدر الحقيقة
├── Makefile                 # واجهة التشغيل الموحّدة
├── .env.example             # قالب البيئة — لا أسرار
└── PROJECT-BASELINE.md      # نقطة المرجع المركزية
```

### RS-001 — حدود المستودع الواحد (MANDATORY)

المشروع **مستودع واحد (monorepo)** يضم الواجهة والخلفية والتوثيق.

**المبرر:** العقود بين الواجهة والخلفية تتغير معًا؛ فصلهما إلى مستودعين يُنتج انحرافًا في العقد لا يكتشفه أحد حتى وقت التشغيل. والمشروع فريق واحد لا فريقين.

### RS-002 — النماذج التصميمية لا تُبنى ولا تُنشر (MANDATORY)

`admin-ui/` و`docs/02-design/client-app/` **نماذج مرجعية ثابتة**. لا تدخل أي خط بناء، ولا تُنشر، ولا يُستورد منها كود إلى `frontend/`.

**ما يُنقل منها:** القرارات البصرية والسلوكية **قراءةً** عند بناء المكوّن المقابل في React. لا نسخ لصق لـHTML أو jQuery — حزمة الواجهة React لا jQuery.

### RS-003 — لا أسرار في المستودع (MANDATORY)

`.env` مُستثنى في `.gitignore`. القالب `.env.example` يحمل **أسماء المفاتيح وقيمًا وهمية فقط**.

> ⚠️ **قيد `VITE_*`:** متغيرات الواجهة تُحقن **وقت البناء** وتظهر في الحزمة المنشورة. **لا يجوز أن تحمل أي سر**.

## 3. بنية الخلفية — Laravel Modular Monolith

### RS-010 — الموديول مجلد (MANDATORY)

```text
backend/
├── app/
│   ├── Modules/                    # ★ الموديولات — قلب المعمارية
│   │   ├── Orders/                 # موديول الطلبات (ORD)
│   │   ├── Customers/              # موديول العملاء (CUS)
│   │   ├── Invoices/               # موديول الفواتير (INV)
│   │   ├── ...
│   │   └── AuditLog/               # موديول سجل التدقيق
│   │
│   ├── Shared/                     # ★ ما لا يملكه موديول بعينه
│   │   ├── Contracts/              # عقود M2M — الواجهات فقط
│   │   ├── Events/                 # عقد الحدث الأساسي
│   │   ├── Exceptions/             # هرم الأخطاء العام (ECS-*)
│   │   ├── Http/                   # Middleware · Response envelope
│   │   └── Support/                # أدوات عامة بلا منطق أعمال
│   │
│   └── Providers/
├── config/
├── database/
│   └── migrations/                 # ⚠️ لا migrations هنا — انظر RS-014
├── routes/
│   ├── api.php                     # تجميع فقط — لا تعريف مسارات
│   └── console.php
├── tests/
│   ├── Unit/
│   ├── Feature/
│   └── Integration/
└── composer.json
```

### RS-011 — البنية الداخلية للموديول (MANDATORY)

كل موديول يلتزم بأربع طبقات — تنزيلًا مباشرًا لـ`EP-ARCH-002`:

```text
app/Modules/Orders/
├── Domain/                         # قلب الموديول — لا يعرف Laravel
│   ├── Models/                     # Eloquent models
│   ├── Enums/                      # التعدادات (order_status …)
│   ├── ValueObjects/
│   └── Events/                     # أحداث النطاق (EVT-ORD-###)
│
├── Application/                    # حالات الاستخدام
│   ├── Services/                   # منطق الأعمال — BR-ORD-###
│   ├── DTOs/
│   └── Policies/                   # التفويض — PERM-ORD-###
│
├── Infrastructure/                 # التفاصيل القابلة للاستبدال
│   ├── Repositories/
│   ├── Migrations/                 # ★ migrations الموديول (RS-014)
│   └── Seeders/
│
├── Http/                           # الحافة
│   ├── Controllers/
│   ├── Requests/                   # التحقق — VAL-*
│   ├── Resources/                  # تشكيل الاستجابة
│   └── routes.php                  # ★ مسارات الموديول (RS-016)
│
├── Contracts/                      # ★ ما يعرضه للموديولات الأخرى
│   └── OrdersServiceInterface.php
│
└── OrdersServiceProvider.php       # تسجيل الموديول
```

### RS-012 — أسماء مجلدات الموديولات (MANDATORY)

اسم المجلد = **اسم الموديول الكامل** بصيغة `PascalCase`، مطابقًا لاسم مجلد
التوثيق في `docs/01-modules/`:

| Module | الكود | مجلد التوثيق | مجلد الكود |
|---|---|---|---|
| `{{MODULE_ID}}` | `ORD` | `docs/01-modules/orders/` | `Orders/` |
| `{{MODULE_ID}}` | `CUS` | `docs/01-modules/customers/` | `Customers/` |
| `{{MODULE_ID}}` | `INV` | `docs/01-modules/invoices/` | `Invoices/` |
| `{{MODULE_ID}}` | `INF` | `docs/01-modules/infrastructure/` | — بلا مجلد |

> **موديول البنية التحتية بلا مجلد** — بنية تحتية لا كود تطبيقي.
>
> **الكود لا يُلغى** — يبقى مرجعَ بادئة الجدول (`RS-013`) وقطاع المسار
> (`API-005`) والمعرّفات (`FR-ORD-*` · `API-ORD-*`). المجلد وحده يحمل الاسم الكامل.
>
> **المجلد ليس الكود.** أي أداة تشتقّ الكود بتصغير اسم المجلد
> **تنكسر صامتةً** — انظر التحذير في `RS-013`. الخريطة الرسمية بين المجلد
> والكود تُسجَّل صراحةً في `scripts/arch-check.sh`.

### RS-013 — بادئة الجداول تطابق كود الموديول (MANDATORY)

جدول `ord_orders` ينتمي حصرًا إلى الموديول الذي **كوده** `ord` — أي
`app/Modules/Orders/`. البادئة (`DMOD-002`) والكود **وجهان لملكية واحدة**.

**الاستثناء الموثَّق الوحيد:** جداول موديول الإعدادات المرجعية بلا بادئة (`regions`,
`languages`, `system_settings` …) — قرار قائم في `data-model.md` لذلك الموديول.
تبقى مملوكة لموديول الإعدادات المرجعية رغم غياب البادئة. المعيار أنها **لا تحمل
بادئة موديول آخر** — لا أنها بلا شرطة سفلية؛ `system_settings` مرجعيّ رغم احتوائه عليها.

> ⚠️ **المجلد ليس الكود.** كل فحص آليّ يربط جدولًا
> بموديوله يجب أن يقرأ الكود من **خريطة صريحة** لا أن يشتقّه من اسم المجلد.
> الخريطة الرسمية في `scripts/arch-check.sh` (`module_code()`)، ومجلدٌ غير
> مسجَّل فيها = خرق `RS-012` يُرصد لا يُتجاوز.
>
> اشتقاق البادئة من اسم المجلد يُنتج إيجابيات كاذبة تتّهم
> `ord_orders` بأنه أجنبيّ عن موديوله، وتحت تسمية `RS-022` بينما السبب تسمية.
> **الملكية تُشتَق ممّا يُنشئه الموديول فعلًا (`Schema::create`).**

### RS-014 — migrations داخل الموديول لا في الجذر (MANDATORY)

```text
✅ app/Modules/Orders/Infrastructure/Migrations/2026_01_01_000001_create_ord_orders_table.php
❌ database/migrations/2026_01_01_000001_create_ord_orders_table.php
```

**المبرر:** وضع كل migration في مجلد جذري واحد يُلغي الملكية عمليًا — تصبح عشرات الموديولات تكتب في دلو واحد، ويستحيل معرفة من يملك جدولًا بالنظر إلى البنية. وفصل الموديول لاحقًا (`EP-ARCH-003`) يتطلب حينها فرزًا يدويًا لمئات الملفات.

`database/migrations/` يبقى **فارغًا** إلا من migrations إطار العمل نفسه (jobs · cache · sessions).

### RS-015 — التحميل الديناميكي للـmigrations (MANDATORY)

يسجّل كل `ServiceProvider` مسار migrations موديوله:

```php
$this->loadMigrationsFrom(__DIR__ . '/Infrastructure/Migrations');
```

### RS-016 — مسارات الموديول داخله (MANDATORY)

`routes/api.php` **ملف تجميع لا تعريف**. كل موديول يعرّف مساراته في `Http/routes.php` ويُحمّلها عبر مزوّده.

**المبرر نفسه:** ملف مسارات مركزي بمئات السطور يجعل كل تغيير في أي موديول يلمس ملفًا واحدًا مشتركًا — تعارضات دمج دائمة وملكية ضائعة.

### RS-017 — بادئة المسار تطابق الموديول (MANDATORY)

> ⚠️ **الصيغة يملكها `API-005` في `api-design-standard.md` — لا هذا المعيار.** ما هنا **إحالة لا تعريف**؛ عند أي تعارض **يسود `api-design-standard.md`**.

**الصيغة المعتمدة (`API-005` · `MANDATORY`):**

```text
/api/v{N}/{module-code}/{resource-plural}
/api/v{N}/{module-code}/{resource-plural}/{id}
```

| النمط | مثال |
|---|---|
| مسار العميل | `/api/v1/ord/orders` |
| مسار إداري | `/api/v1/ord/admin/orders` |
| فعل أعمال (`API-007`) | `/api/v1/ord/admin/orders/{id}/actions/cancel` |

> **`{module-code}` يسبق `admin` دائمًا** — لأن المسار يعبّر عن **الملكية** أولًا. القطاع `admin` تمييز نطاق داخل الموديول لا بديل عن كوده. تعريف الصيغة نفسها في معيارين هو ما يُنتج التعارض — فالصيغة تُعرَّف في موضع واحد ويُحال إليها.

> **الإصدار `v1` إلزامي من اليوم الأول** — إضافته لاحقًا تكسر كل مستهلك قائم. سياسة الإهمال والانتقال إلى `v2` تُحسم لكل مشروع (`API-028`).

## 4. حدود الموديولات — القواعد الحاسمة

### RS-020 — لا استيراد مباشر عبر الحدود (MANDATORY)

```php
// ❌ محظور — استيراد نموذج موديول آخر مباشرة
use App\Modules\Customers\Domain\Models\Customer;

// ✅ مسموح — العقد المُصرَّح به
use App\Shared\Contracts\Customers\CustomerLookupInterface;
```

**ما يجوز استيراده من موديول آخر:** ما في `Contracts/` **فقط**. كل ما في `Domain/` و`Application/` و`Infrastructure/` و`Http/` **خاص بالموديول**.

### RS-021 — لا استعلام عابر للحدود (MANDATORY)

```php
// ❌ محظور — JOIN عبر حدود الموديول
DB::table('ord_orders')->join('cus_customers', ...)

// ✅ مسموح — عقد قراءة
$customer = $this->customerLookup->findPublicProfile($order->customer_id);
```

**تنزيل `EP-ARCH-003`:** الـJOIN العابر هو **بالضبط** ما يمنع فصل الموديول لاحقًا — لأنه يفترض أن الجدولين في قاعدة بيانات واحدة إلى الأبد.

### RS-022 — لا مفاتيح أجنبية عابرة (MANDATORY)

`DMOD-024`: كل إشارة عابرة **FK منطقي** يُطبَّق في طبقة التطبيق، **بلا قيد `FOREIGN KEY`** على مستوى قاعدة البيانات.

| النطاق | القيد |
|---|---|
| داخل الموديول | `FOREIGN KEY` مُنفَّذ ✅ |
| عابر للموديولات | FK منطقي — تطبيقي فقط ❌ |

### RS-023 — العقود في `Shared/Contracts` (MANDATORY)

```text
app/Shared/Contracts/
├── Customers/CustomerLookupInterface.php
├── Orders/OrderServiceInterface.php              # API-ORD-012
├── Payments/PaymentServiceInterface.php
├── MediaManagement/MediaServiceInterface.php
├── Notifications/NotificationServiceInterface.php
└── AuditLog/AuditLoggerInterface.php
```

> **مجلد العقد يحمل اسم الموديول المالك كاملًا** — نفس أسماء `RS-012`. عقدٌ
> تحت اسم مختصر يفصل العقد عن مالكه بالضبط حيث تُقرأ الملكية أول مرة.

**قاعدة:** الواجهة في `Shared/`، والتنفيذ في مجلد الموديول المالك. المستهلك يعتمد على الواجهة، والحاوية تحقن التنفيذ. **هذا هو ما يجعل الفصل المستقبلي تغييرَ ربطٍ لا إعادةَ كتابة.**

### RS-024 — معرّف العقد في التوثيق البرمجي (MANDATORY)

كل دالة عقد تحمل معرّفها من وثيقة الموديول:

```php
/**
 * وسم الطلب مُنفَّذًا كأثر لعملية في موديول آخر.
 *
 * @contract API-ORD-012
 * @see docs/01-modules/orders/api-contracts.md
 * @see docs/99-quality/cross-module-contract-registry.md
 */
public function markFulfilled(
    int $orderId, int $actorId,
    string $sourceModule, int $transactionId
): void;
```

**المبرر:** انحراف الكود عن العقد أكثر أعطال التكامل شيوعًا — وقد وُثِّق أكثر من مثال عليه في المشروع الأصل. المعرّف في التوثيق يجعل الانحراف قابلًا للاكتشاف بالبحث النصي.

### RS-025 — لا اعتمادية دائرية (MANDATORY)

`EP-XMOD-004`. عند اكتشاف دورة: **تُرفع كقرار معماري ولا تُحلّ بحقنة متبادلة**.

## 5. بنية الواجهة — React + TypeScript + Vite

### RS-030 — التنظيم بالميزة لا بالنوع (MANDATORY)

```text
frontend/
├── src/
│   ├── modules/                    # ★ مرآة لموديولات الخلفية
│   │   ├── orders/
│   │   │   ├── api/                # استدعاءات الموديول
│   │   │   ├── components/
│   │   │   ├── hooks/
│   │   │   ├── types/              # أنواع مشتقة من عقود API
│   │   │   └── routes.tsx
│   │   ├── customers/
│   │   └── invoices/
│   │
│   ├── shared/
│   │   ├── api/                    # عميل HTTP · مغلّف الاستجابة · معالجة الأخطاء
│   │   ├── components/             # مكوّنات عامة
│   │   ├── hooks/
│   │   ├── i18n/                   # لغة المنصة الأساسية واتجاهها
│   │   └── types/
│   │
│   ├── app/                        # التهيئة · التوجيه · المزوّدات
│   └── main.tsx
├── public/
├── index.html
├── vite.config.ts
├── tsconfig.json
└── package.json
```

**المبرر:** التنظيم بالنوع (`components/` واحد يضم كل شيء) ينهار عند عشرات الشاشات. التنظيم بالميزة يُبقي التغيير موضعيًا ويجعل حدود الموديول مرئية في الواجهة كما هي في الخلفية.

> **اسم مجلد الموديول في الواجهة = اسم مجلد التوثيق بـ`kebab-case`** — أي
> نظير `RS-012` نفسه (`Orders/` ⇐ `orders/`)، وهو حرفيًا اسم مجلد
> الموديول في `docs/01-modules/`. اسم واحد للموديول عبر التوثيق والخلفية
> والواجهة، فلا يحتاج القارئ قاموسًا لعبور الطبقات.

### RS-031 — اتجاه اللغة الأساسية أساس لا إضافة (MANDATORY)

لغة المنصة الأساسية واتجاهها على الجذر (الافتراضي في الإطار: `dir="rtl"` و`lang="ar"`). اللغة الثانية إن وُجدت لاحقًا **إضافة**، والعكس غير صحيح.

### RS-032 — لا منطق أعمال في الواجهة (MANDATORY)

الواجهة تعرض وتتحقق **شكليًا** (صيغة · إلزامية · نطاق). كل قاعدة `BR-*` تُنفَّذ في الخلفية.

**التحقق الشكلي في الواجهة تحسين تجربة — لا حماية.** كل قاعدة تُطبَّق في الخلفية بصرف النظر عن الواجهة.

### RS-033 — الأنواع مشتقة من العقود (MANDATORY)

أنواع TypeScript للاستجابات تُشتق من `api-contracts.md` للموديول المالك. **لا نوع مُخترع في الواجهة** لحقل غير موجود في العقد.

## 6. الاختبارات

### RS-040 — موضع الاختبار يتبع نطاقه (MANDATORY)

| النوع | الموضع | يختبر |
|---|---|---|
| Unit | `backend/tests/Unit/Modules/{Module}/` | منطق داخلي معزول |
| Feature | `backend/tests/Feature/Modules/{Module}/` | نقطة API كاملة |
| Integration | `backend/tests/Integration/` | **عبور الحدود** — عقود M2M |
| Frontend | `frontend/src/modules/{module}/**/*.test.tsx` | بجوار الكود |

### RS-041 — معرّف السيناريو في اسم الاختبار (MANDATORY)

```php
/** @scenario TS-ORD-001 */
public function test_order_requires_verified_customer(): void
```

**المبرر:** يجعل تغطية `test-scenarios.md` قابلة للقياس آليًا بدل التقدير.

## 7. المحظورات

| # | محظور | البديل | المرجع |
|---|---|---|---|
| 1 | `use App\Modules\X\Domain\...` عبر الحدود | عقد في `Shared/Contracts` | RS-020 |
| 2 | `JOIN` عابر للموديولات | عقد قراءة | RS-021 |
| 3 | `FOREIGN KEY` عابر | FK منطقي تطبيقي | RS-022 · `DMOD-024` |
| 4 | migration في `database/migrations/` | مجلد الموديول | RS-014 |

### 9.1 `RS-OD-01` — لماذا أداتان لا واحدة

فحصٌ واحد لا يغطي القواعد كلها. التقسيم **بحسب ما تراه الأداة**:

| القاعدة | الأداة | السبب |
|---|---|---|
| `RS-020` لا استيراد عابر | **Deptrac** | يحلّل رسم الاعتماديات بين الأصناف — وهذا ما لا يفعله بحث نصي بدقة |
| `RS-023` العبور عبر العقود | **Deptrac** | يُعبَّر عنه بطبقات وقواعد سماح تعريفية |
| `RS-025` لا دورات | **Deptrac** | كشف الدورات يحتاج الرسم كاملًا |
| `RS-014` migrations في الموديول | `arch-check.sh` | قاعدة **موضع ملف** — محلّل الأصناف لا يراها |
| `RS-016` لا مسار مركزي | `arch-check.sh` | قاعدة **محتوى ملف** |
| `RS-021` لا JOIN عابر | `arch-check.sh` | اسم الجدول **سلسلة نصية** لا صنف |
| `RS-022` لا FK عابر | `arch-check.sh` | المِثل — داخل استدعاء `constrained()` |

**إضافة مُستفادة من التجربة:** يُفعَّل مُصدِّر `use` في `deptrac.yaml`. المُصدِّر الافتراضي يفحص المراجع الفعلية، فيمر استيراد `use` غير مستخدَم بلا رصد — **وقد تُحقِّق من ذلك عمليًا** بحقن استيراد عابر: لم يُرصد حتى أُضيف استخدام حقيقي. الاستيراد غير المستخدَم **نية عبور مُعلَنة** تسبق الاستخدام بخطوة.

> **البوابة مُختبَرة لا مُفترَضة:** يُحقن خرق متعمَّد فيُنتج `EXIT_CODE=1` برسالة من قبيل `AuditLog must not depend on Customers`، ثم يُعاد الملف. بوابة لم تفشل قط لا تُثبت شيئًا.
