# Audit Logging Standard — معيار سجل التدقيق

> يُحدد هذا المعيار القواعد العامة لنظام Audit Log: البنية، المحتوى الإلزامي، الثبات، الاحتفاظ، معالجة الفشل، والإجراءات الخاضعة للتدقيق.
>
> يبني على `EP-AUD-001..006`.
>
> **الملكية:** موديول سجل التدقيق (`{{MODULE_CODE}}`) هو المالك الحصري لنظام Audit Log (`EP-AUD-002`).

---

## 0. الغرض والنطاق

يُحدد: بنية سجل التدقيق، المحتوى الإلزامي لكل سجل، الإجراءات الخاضعة للتدقيق، الثبات وعدم قابلية الحذف، مدة الاحتفاظ، سلوك النظام عند فشل الكتابة، والفصل بين Audit Log وLogging التقني.

## 2. الملكية والاستهلاك

### AUD-001 — موديول سجل التدقيق مالك حصري

**التصنيف:** `MANDATORY`

موديول سجل التدقيق (`{{MODULE_CODE}}`) يملك نظام Audit Log حصريًا (`EP-AUD-002`). جميع الموديولات تُرسل سجلاتها إليه ولا تُنشئ نظام تدقيق بديل.

### AUD-002 — الفصل عن Logging التقني

**التصنيف:** `MANDATORY`

Audit Log (حوكمة ورقابة — موديول سجل التدقيق) و Logging التقني (تشخيص وأداء — موديول البنية التحتية والمراقبة `{{MODULE_CODE}}`) نظامان منفصلان (`EP-OBS-001`):

- Audit Log ثابت نهائيًا ولا يُحذف.
- Logging التقني قابل للحذف حسب سياسة الاحتفاظ.

## 3. بنية السجل

### AUD-003 — الحقول الإلزامية

**التصنيف:** `MANDATORY`

كل سجل تدقيق يتضمن — كحد أدنى (`EP-AUD-005`، `architecture-template.md` — قسم Audit Log):

| الحقل | الوصف | ملاحظات |
|---|---|---|
| `id` | معرّف السجل | فريد |
| `actor_id` | معرّف الفاعل | مرجع إلى كيان المستخدم في موديول الهوية |
| `actor_role` | دور الفاعل وقت التنفيذ | الدور النشط |
| `action_type` | نوع الإجراء | من قائمة الإجراءات المعتمدة (§4) |
| `entity_type` | نوع الكيان المتأثر | مثل: `Order`, `Invoice`, `User` |
| `entity_id` | معرّف الكيان المتأثر | |
| `module_code` | الموديول المصدر | |
| `previous_value` | القيمة السابقة | عند التعديل — JSON |
| `new_value` | القيمة الجديدة | عند التعديل — JSON |
| `reason` | السبب أو الملاحظة | إلزامي للإجراءات التي تتطلب مبررًا (`DD-025`) |
| `timestamp` | وقت التنفيذ | ISO 8601 UTC (`DD-004`) |
| `ip_address` | عنوان IP | عند توفره |
| `correlation_id` | معرّف الارتباط | عند توفره (`EP-OBS-004`) |

### AUD-004 — أمن المحتوى

**التصنيف:** `MANDATORY`

- لا تُسجل أسرار (كلمات مرور، مفاتيح، tokens) في Audit Log (`SEC-007`).
- لا تُسجل بيانات حساسة كاملة (رقم جوال كامل، وثائق هوية).
- القيم الحساسة تُخفى أو تُحذف من `previous_value`/`new_value`.

## 4. الإجراءات الخاضعة للتدقيق

### AUD-005 — القائمة الأساسية

**التصنيف:** `MANDATORY`

كحد أدنى (`EP-AUD-001`، `architecture-template.md` — قسم Audit Log):

| الفئة | الإجراءات |
|---|---|
| **المستخدمون والأدوار** | اعتماد/رفض توثيق مستخدم أو دور، تعليق/تفعيل حساب، تعديل صلاحيات |
| **الكيانات الجوهرية** | تغيير حالة توثيق كيان، إخفاء/إعادة إظهار سجل |
| **المعاملات التجارية** | إنشاء/إلغاء معاملة، تغيير حالات المعاملة |
| **المالية** | تعديل العمولات أو الرسوم أو الباقات، تعديل المبالغ المحجوزة أو التأمينات، معالجة فشل الدفع، التحويل إلى طرف بديل |
| **الإعدادات** | تعديل الإعدادات الحساسة |
| **الإدارة** | كل إجراء يخضع لبوابة `HG-E-03` (`AUTHZ-016`) |

### AUD-006 — توثيق الإجراءات في كل موديول

**التصنيف:** `MANDATORY`

كل موديول يوثق إجراءاته الخاضعة للتدقيق في حزمة التنفيذ الهندسية:

| الحقل | الوصف |
|---|---|
| الإجراء | وصف الإجراء |
| `action_type` | المعرّف (مثل: `USER_SUSPENDED`, `ORDER_CANCELLED`) |
| الدور المنفذ | من يملك صلاحية هذا الإجراء |
| يتطلب سببًا | نعم / لا |
| الحقول المسجلة | ما يُسجل في `previous_value`/`new_value` |

## 5. الثبات والاحتفاظ

### AUD-007 — لا حذف ولا تعديل

**التصنيف:** `MANDATORY`

سجلات Audit Log ثابتة نهائيًا (`EP-AUD-003`):

- لا يُسمح بعملية `DELETE` على سجلات التدقيق.
- لا يُسمح بعملية `UPDATE` على سجلات التدقيق.
- هذا قيد صلب على مستوى قاعدة البيانات وليس فقط قيد تطبيقي.

### AUD-008 — مدة الاحتفاظ

**التصنيف:** `MANDATORY`

- المدة الافتراضية: `{{AUDIT_RETENTION_MONTHS}}` شهرًا (`EP-AUD-004`) — القيمة في المشروع المرجعي 12 شهرًا، وتُثبَّت لكل مشروع بقرار معتمد.
- قابلة للضبط بصلاحية SYSADMIN عبر موديول الإعدادات (`{{MODULE_CODE}}`).
- بعد انتهاء المدة: يمكن الأرشفة (نقل إلى تخزين بارد) ولكن لا الحذف.

## 6. معالجة الفشل

### AUD-009 — استمرار الخدمة

**التصنيف:** `MANDATORY`

عند فشل كتابة سجل التدقيق (`EP-AUD-006`):

1. يستمر النظام في تقديم الخدمة — لا يُوقف.
2. يُرسل تنبيه فوري لـ SYSADMIN.
3. يُسجل الفشل في Logging التقني (موديول البنية التحتية والمراقبة).
4. يُعاد المحاولة عند استعادة النظام.

## 7. الوصول والصلاحيات

### AUD-010 — صلاحيات الوصول

**التصنيف:** `MANDATORY`

| الدور | الصلاحية |
|---|---|
| `SYSADMIN` | عرض جميع سجلات التدقيق |
| `SUPERVISOR` | عرض سجلات التدقيق ضمن نطاق الموديول المسؤول عنه |
| المستخدم العادي | لا وصول لسجلات التدقيق |

تفاصيل الصلاحيات تُحدد في `permission-matrix.md` الخاص بموديول سجل التدقيق.

### AUD-011 — لا تعديل من الواجهة

**التصنيف:** `PROHIBITED`

لا توجد واجهة أو API تسمح بتعديل أو حذف سجلات التدقيق. واجهة موديول سجل التدقيق للقراءة والبحث والتصدير فقط.
