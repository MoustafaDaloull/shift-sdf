# Notification Contract Standard — معيار عقود الإشعارات

> يُحدد هذا المعيار القواعد العامة لنظام الإشعارات: القنوات، القوالب، التسليم، إعادة المحاولة، اللغة، والتفضيلات.
>
> يبني على `EP-RETRY-002` وقسم التكاملات في `architecture-template.md`.
>
> **الملكية:** موديول الإشعارات (`{{MODULE_CODE}}`) هو المالك الحصري لنظام الإشعارات.

---

## 0. الغرض والنطاق

يُحدد: قنوات الإشعارات المعتمدة، قواعد التسليم وإعادة المحاولة، إدارة القوالب، تفضيلات المستخدم، اللغة، وتوثيق عقود الإشعارات في كل موديول.

## 2. الملكية والاستهلاك

### NTF-001 — موديول الإشعارات مالك حصري

**التصنيف:** `MANDATORY`

كل عملية إرسال إشعار تمر عبر موديول الإشعارات (`{{MODULE_CODE}}`). الموديولات المستهلكة تطلب الإشعار عبر الحدث أو الاستدعاء الداخلي، ولا تُرسل إشعارات مباشرة.

---

## 3. القنوات المعتمدة

### NTF-002 — القنوات

**التصنيف:** `MANDATORY`

القنوات المتاحة للمنصة، وتُعتمد كل قناة لكل مشروع بقرار مسجَّل في `project-decisions.md` مع نطاق استخدامها:

| القناة | الحالة | الاستخدام النموذجي |
|---|---|---|
| SMS | `{{STATUS}}` | OTP، تنبيهات حرجة |
| WhatsApp | `{{STATUS}}` | OTP، وقد يُقيَّد بها وحدها في الإصدار الأول |
| Email | `{{STATUS}}` | إيصالات، تقارير، إشعارات غير عاجلة |
| Push | `{{STATUS}}` | تنبيهات فورية داخل التطبيق |
| In-App | `{{STATUS}}` | إشعارات داخلية داخل المنصة |

### NTF-003 — اختيار القناة

**التصنيف:** `MANDATORY`

لكل نوع إشعار يُحدد في `notification-contracts.md` الخاص بالموديول:

- القناة الأساسية.
- القنوات البديلة (Fallback) إن وجدت.
- هل القناة إلزامية أم قابلة للتعطيل من المستخدم.

---

## 4. التسليم وإعادة المحاولة

### NTF-004 — إعادة المحاولة

**التصنيف:** `MANDATORY`

عند فشل التسليم: 3 محاولات كل 5 دقائق (`EP-RETRY-002`). تُثبَّت القيمتان لكل مشروع بقرار معتمد وتُقرآن من موديول الإعدادات.

### NTF-005 — بعد استنفاد المحاولات

**التصنيف:** `MANDATORY`

عند استنفاد المحاولات:

1. تسجيل الفشل مع التفاصيل (القناة، المستلم، السبب).
2. تنبيه مراقبة النظام (`EP-OBS-002`).
3. تحديث حالة الإشعار إلى `failed`.
4. لا يُوقف النظام بسبب فشل الإشعار.

### NTF-006 — حالات الإشعار

**التصنيف:** `MANDATORY`

| الحالة | الوصف |
|---|---|
| `pending` | في انتظار الإرسال |
| `sent` | أُرسل بنجاح للمزود |
| `delivered` | وصل للمستلم (إن وفره المزود) |
| `failed` | فشل نهائي بعد استنفاد المحاولات |
| `read` | قرأه المستلم (In-App فقط) |

## 5. القوالب والمحتوى

### NTF-007 — القوالب

**التصنيف:** `MANDATORY`

كل إشعار يستخدم قالبًا مُعرَّفًا:

- اسم القالب (معرّف فريد).
- القناة المستهدفة.
- المتغيرات المطلوبة (مثل: `{customer_name}`, `{order_number}`).
- النص العربي (إلزامي).
- النص الإنجليزي (إلزامي لدعم اللغتين).

### NTF-008 — أمن المحتوى

**التصنيف:** `MANDATORY`

- لا تُضمن بيانات حساسة في محتوى الإشعار (`SEC-004`).
- لا أرقام جوال كاملة أو وثائق هوية أو مبالغ تفصيلية في SMS أو Push.
- يمكن تضمين رابط للتفاصيل داخل المنصة.

---

## 6. اللغة والتفضيلات

### NTF-009 — لغة الإشعار

**التصنيف:** `MANDATORY`

الإشعار يُرسل بلغة حساب المستلم. اللغة الافتراضية هي اللغة الأساسية للمنصة المعتمدة في `business-rules-global.md`.

### NTF-010 — تفضيلات المستخدم

**التصنيف:** `MANDATORY`

المستخدم يمكنه إدارة تفضيلات الإشعارات:

- تفعيل/تعطيل قنوات غير إلزامية.
- لا يمكن تعطيل إشعارات الأمان (OTP، تغيير كلمة المرور، تعليق الحساب).

---

## 7. توثيق عقود الإشعارات

### NTF-011 — عقد الإشعار في كل موديول

**التصنيف:** `MANDATORY`

كل موديول يوثق إشعاراته في `notification-contracts.md` ضمن حزمة التنفيذ الهندسية:

| الحقل | الوصف |
|---|---|
| معرّف الإشعار | `NTF-[MODULE-CODE]-###` |
| الحدث المحفز | الحدث أو الإجراء الذي يُحفز الإشعار |
| القناة | القناة الأساسية والبديلة |
| المستلم | الدور أو المستخدم المستهدف |
| القالب | معرّف القالب |
| الأولوية | عاجل / عادي |
| إلزامي | هل يمكن للمستخدم تعطيله |

## 8. بوابة الجودة

### NTF-012 — قائمة التحقق

**التصنيف:** `MANDATORY`

| # | البند | المرجع |
|---|---|---|
| 1 | كل إشعار يمر عبر موديول الإشعارات | `NTF-001` |
| 2 | القنوات المستخدمة معتمدة | `NTF-002` |
| 3 | إعادة المحاولة مُطبقة (3×5 دقائق) | `NTF-004` |
| 4 | لا بيانات حساسة في المحتوى | `NTF-008` |
| 5 | الإشعار يُرسل بلغة المستلم | `NTF-009` |
| 6 | إشعارات الأمان غير قابلة للتعطيل | `NTF-010` |
| 7 | عقد الإشعار موثق لكل موديول | `NTF-011` |
