# معايير كتابة الكود — Coding Standards

> **الغرض:** تحويل المعايير الهندسية من قواعد على الورق إلى **أنماط كتابة ملزمة** — لأن المعيار الذي لا يُترجَم إلى نمط كتابة محدد يُقرأ مرة ويُنسى.
>
> **ما لا يحدده:** بنية المجلدات (`repository-structure.md`) · آليات الفرض الآلي (`automation-strategy.md`).
>
> **قاعدة القراءة:** ما لم يُذكر هنا صراحةً، يسري **PSR-12** للخلفية والافتراضي المُوصى به لـReact/TypeScript.
>
> القواعد المرتبطة بحزمة تقنية بعينها تُطبَّق عبر ملف تعريف الحزمة `profiles/<name>/`؛ الافتراضي `laravel-react`.

## 1. القواعد العابرة للغتين

### CS-001 — لغة المستخدم للمستخدم · الإنجليزية للكود (MANDATORY)

| العنصر | اللغة |
|---|---|
| أسماء المتغيرات والدوال والأصناف والملفات | **إنجليزية** |
| رسائل المستخدم النهائي | **لغة المنصة الأساسية** (الافتراضي: العربية) |
| التعليقات التفسيرية | إنجليزية |
| معرّفات الأخطاء والعقود | إنجليزية (`ERR-ORD-VAL-001`) |
| التوثيق البرمجي المرجعي (`@contract`) | إنجليزية |

### CS-002 — التعليق يشرح السبب لا الفعل (MANDATORY)

```php
// ❌ يكرر ما يقوله الكود
// نتحقق من أن الحالة نشطة
if ($customer->account_status !== AccountStatus::Active) { ... }

// ✅ يشرح ما لا يقوله الكود
// BR-CUS-016: الحساب المقيَّد يقرأ ولا يكتب — بخلاف المعطَّل الذي يُمنع كليًا.
// التمييز مقصود: المقيَّد قد يكون تحت مراجعة ولا يجوز قطع وصوله للبيانات.
if ($customer->account_status !== AccountStatus::Active) { ... }
```

### CS-003 — كل قاعدة أعمال تحمل معرّفها (MANDATORY)

كل تنفيذ لقاعدة `BR-*` يذكرها في تعليق مجاور. **بلا استثناء.**

**المبرر:** بعد ستة أشهر يصبح السؤال «لماذا 48 ساعة؟» بلا جواب — ويُغيّرها أحدهم. `BR-ORD-026` في التعليق تجعل الجواب على بُعد بحث نصي واحد.

### CS-004 — لا رقم سحري ولا نص سحري (MANDATORY)

```php
// ❌
if ($hoursSinceAccepted > 48) { ... }

// ✅ — القيمة قابلة للضبط من موديول الإعدادات
$window = $this->settings->get('ord.payment_window_hours', 48);
if ($hoursSinceAccepted > $window) { ... }
```

كل قيمة عمل قابلة للضبط **تُقرأ من موديول الإعدادات** لا تُكتب في الكود.

### CS-005 — الاسم يصف الغرض لا التنفيذ (MANDATORY)

```php
❌ $data, $temp, $result, $flag, $arr
✅ $pendingOrders, $paymentDeadline, $isReceiptConfirmed
```

### CS-006 — لا كود ميت (MANDATORY)

الكود المُعطَّل بالتعليق يُحذف. Git يحفظه — والتعليق لا يحفظ إلا الالتباس.

## 2. الخلفية — PHP / Laravel

### CS-010 — PSR-12 + الأنواع الصارمة (MANDATORY)

```php
<?php

declare(strict_types=1);

namespace App\Modules\Orders\Application\Services;
```

`declare(strict_types=1)` **في كل ملف PHP بلا استثناء**.

### CS-011 — تصريح الأنواع كامل (MANDATORY)

كل معامل وكل قيمة إرجاع مُصرَّح النوع — بما فيها `void` و`never`.

```php
public function confirmReceipt(int $orderId, int $customerId): ReceiptConfirmation
```

### CS-012 — التسمية (MANDATORY)

| العنصر | النمط | مثال |
|---|---|---|
| الصنف · الواجهة · التعداد | `PascalCase` | `OrderService` |
| الدالة · المتغير | `camelCase` | `confirmReceipt()` |
| الثابت · حالة التعداد | `PascalCase` داخل `enum` | `AccountStatus::Active` |
| الجدول | `snake_case` بالبادئة | `ord_orders` |
| العمود | `snake_case` | `receipt_confirmed_at` |
| الملف | يطابق اسم الصنف | `OrderService.php` |

### CS-013 — لواحق الأصناف تدل على طبقتها (MANDATORY)

| الطبقة | اللاحقة | مثال |
|---|---|---|
| خدمة أعمال | `Service` | `OrderService` |
| مستودع | `Repository` | `CustomerRepository` |
| عقد | `Interface` | `PaymentServiceInterface` |
| طلب تحقق | `Request` | `StoreOrderRequest` |
| تشكيل استجابة | `Resource` | `OrderResource` |
| سياسة تفويض | `Policy` | `OrderPolicy` |
| حدث نطاق | فعل ماضٍ | `ReceiptConfirmed` |
| استثناء | `Exception` | `InsufficientBalanceException` |

### CS-014 — Controller نحيف (MANDATORY)

المتحكم يفعل ثلاثة أشياء فقط: **يستقبل · يفوّض · يشكّل الاستجابة**. لا منطق أعمال ولا استعلام مباشر.

```php
public function confirmReceipt(ConfirmReceiptRequest $request, int $id): JsonResponse
{
    $result = $this->orderService->confirmReceipt($id, $request->user()->id);
    return ApiResponse::success(new ReceiptResource($result), 'تم تأكيد الاستلام');
}
```

**سقف إرشادي:** متحكم يتجاوز 15 سطرًا في دالة واحدة إشارة إلى منطق في غير موضعه.

### CS-015 — التحقق في `FormRequest` لا في المتحكم (MANDATORY)

```php
class ConfirmReceiptRequest extends FormRequest
{
    public function rules(): array
    {
        return ['order_id' => ['required', 'integer', 'min:1']];
    }

    public function messages(): array
    {
        return ['order_id.required' => 'معرّف الطلب مطلوب'];  // CS-001
    }
}
```

> **تمييز حاسم:** `FormRequest` للتحقق **الشكلي** (`VAL-*`). قواعد الأعمال (`BR-*`) في طبقة الخدمة — لأنها تحتاج حالة النظام لا شكل المدخل.

### CS-016 — مغلّف الاستجابة موحّد (MANDATORY)

```json
{ "success": true,  "data": { }, "message": "..." }
{ "success": false, "error": { "code": "ERR-ORD-VAL-001", "message": "...", "details": { } } }
```

**لا يُبنى المغلّف يدويًا** — عبر `ApiResponse` في `Shared/Http` حصرًا (`API-*` · `ECS-*`).

### CS-017 — الاستثناءات تحمل رمز الخطأ (MANDATORY)

```php
final class OrderNotCancellableException extends BusinessRuleException
{
    public function errorCode(): string { return 'ERR-ORD-BIZ-003'; }
}
```

معالج الاستثناءات المركزي يحوّلها إلى المغلّف. **لا `try/catch` يبتلع خطأ بصمت.**

### CS-018 — لا تسريب في رسالة الخطأ (MANDATORY)

`SEC-*` + `EP-ERR-001`: رسالة المستخدم تقول **ما حدث وما المطلوب** — لا اسم جدول ولا استعلام ولا أثر مكدس.

```php
❌ "SQLSTATE[23000]: Duplicate entry 'x' for key 'cus_customers.email_unique'"
✅ "هذا البريد مستخدم بالفعل"
```

**قاعدة إضافية:** لا تمييز بين «غير موجود» و«غير مصرَّح» في الردود العامة — التمييز يكشف الوجود (`SEC-*`).

### CS-019 — المعاملات المالية ذرّية وصريحة (MANDATORY)

```php
// EP-TXN-003 — كل عملية مالية داخل معاملة صريحة
DB::transaction(function () use ($order) {
    $this->paymentService->capture($order);
    $this->settlementService->schedule($order);   // BR-INV-015
});
```

`EP-TXN-002`: حدود المعاملة **لا تتجاوز حدود الموديول**. استدعاء موديول آخر يقع **خارج** المعاملة أو عبر حدث بعد الالتزام (post-commit).

### CS-020 — الأحداث تُنشر بعد الالتزام (MANDATORY)

```php
DB::transaction(fn () => $order->update(['receipt_confirmed_at' => now()]));
ReceiptConfirmed::dispatch($order);   // EVT-ORD-014 — بعد الالتزام
```

**المبرر:** نشر الحدث داخل المعاملة يعني أن مستهلكًا قد يتصرف على تغيير **يُلغى** بعد لحظة.

### CS-021 — المبالغ `DECIMAL` لا `float` (MANDATORY)

`DMOD-008`: `DECIMAL(12,2)` في قاعدة البيانات، وسلسلة نصية في JSON، وحسابات بدقة عشرية. **`float` ممنوع في أي سياق مالي.**

### CS-022 — التواريخ UTC (MANDATORY)

`DMOD-032`: التخزين والمعالجة بـUTC. التحويل للتوقيت المحلي **في العرض فقط**.

### CS-023 — لا استعلام داخل حلقة (MANDATORY)

مشكلة N+1 تُعالَج بـ`with()` أو استعلام مُجمَّع. **الاختبار: عدد الاستعلامات لا يتغير بتغير عدد السجلات.**

### CS-024 — التفويض في `Policy` لا في الشرط (MANDATORY)

```php
// ❌
if ($user->role === 'SYSADMIN' || $user->id === $order->owner_id) { ... }

// ✅ — AUTHZ-*
$this->authorize('update', $order);
```

> ⚠️ **`HG-E-03`:** تحويل أي صف من `permission-matrix.md` إلى قاعدة تفويض تقنية **يستلزم اجتياز البوابة**.

### CS-025 — Idempotency للعمليات المالية (MANDATORY)

`EP-IDEM-*`: كل عملية مالية تحمل `idempotency_key` فريدًا. تكرار الطلب بالمفتاح نفسه **يعيد النتيجة الأولى ولا ينفّذ ثانيةً**.

### CS-026 — التزامن بقفل صريح (MANDATORY)

```php
// السباق على مورد واحد يتنافس عليه أكثر من طلب — قفل صف
$order = Order::whereKey($id)->lockForUpdate()->firstOrFail();
```

### CS-027 — لا `env()` خارج ملفات الإعداد (MANDATORY)

`config('services.payment_gateway.key')` لا `env('PAYMENT_GATEWAY_KEY')` — لأن `env()` تعيد `null` عند تخزين الإعداد مؤقتًا في الإنتاج.

### CS-028 — Enum بدل السلاسل النصية (MANDATORY)

```php
enum AccountStatus: string
{
    case Active = 'active';
    case Restricted = 'restricted';
    case Suspended = 'suspended';
    case PendingDeletion = 'pending_deletion';   // BR-CUS-016 — خمس حالات
    case Archived = 'archived';
}
```

### CS-029 — سجل التدقيق عبر العقد (MANDATORY)

كل إجراء حساس يُسجَّل عبر `AuditLoggerInterface` (موديول سجل التدقيق). **لا كتابة مباشرة في جدول سجلات التدقيق من أي موديول آخر** (`AUD-007` · Append-only).

## 3. الواجهة — React / TypeScript

### CS-040 — TypeScript صارم (MANDATORY)

```json
{ "strict": true, "noUncheckedIndexedAccess": true, "noImplicitOverride": true }
```

**`any` ممنوع.** عند الضرورة القصوى `unknown` مع تضييق صريح.

### CS-041 — التسمية (MANDATORY)

| العنصر | النمط | مثال |
|---|---|---|
| المكوّن | `PascalCase` | `OrderCard.tsx` |
| الخطّاف | `useCamelCase` | `useOrderTimer.ts` |
| النوع · الواجهة | `PascalCase` | `Order` |
| الثابت | `SCREAMING_SNAKE` | `MAX_UPLOAD_SIZE` |
| ملف غير مكوّن | `camelCase` | `formatCurrency.ts` |

### CS-042 — مكوّنات دالّية فقط (MANDATORY)

لا `class components`. الحالة عبر الخطّافات.

### CS-043 — المكوّن يعرض · الخطّاف يدير (MANDATORY)

منطق جلب البيانات والحالة في خطّاف مخصّص؛ المكوّن يستهلكه ويعرض.

```tsx
export function OrderList() {
  const { orders, isLoading, error, refetch } = useOrders();
  if (isLoading) return <Skeleton />;
  if (error)     return <ErrorState error={error} onRetry={refetch} />;
  if (!orders.length) return <EmptyState />;   // CS-046
  return <>{orders.map(o => <OrderCard key={o.id} order={o} />)}</>;
}
```

### CS-044 — لا استدعاء API مباشر من مكوّن (MANDATORY)

الاستدعاءات في `modules/{module}/api/` عبر العميل المشترك — الذي يتولى المصادقة ومغلّف الاستجابة والأخطاء في موضع واحد.

### CS-045 — الأنواع تطابق العقد (MANDATORY)

`RS-033`: كل نوع استجابة مشتق من `api-contracts.md` للموديول المالك. **حقل غير موجود في العقد لا يُخترع في الواجهة** — يُصحَّح العقد أولًا.

### CS-046 — أربع حالات إلزامية لكل شاشة بيانات (MANDATORY)

| الحالة | المطلوب |
|---|---|
| Loading | مؤشر — لا شاشة بيضاء |
| Empty | رسالة توجيهية + **إجراء مفيد** |
| Error | سبب مفهوم + **زر إعادة محاولة** |
| Success | المحتوى |

**تمييز حاسم:** «لا بيانات» ≠ «صفر». الأولى فراغ والثانية قيمة (قاعدة عمل موديول التقارير).

### CS-047 — لا لون وحده لإيصال حالة (MANDATORY)

كل حالة تُوصَّل بنص أو أيقونة مع اللون. إتاحة أساسية.

### CS-048 — تأكيد الإجراءات غير القابلة للعكس (MANDATORY)

كل إجراء مالي أو تدميري أو ناقل للملكية يمر بتأكيد **يشرح الأثر** — لا «هل أنت متأكد؟» مجردة.

### CS-049 — لا سر في الواجهة (MANDATORY)

`VITE_*` تظهر في الحزمة. المفاتيح السرية في الخادم حصرًا.

### CS-050 — اتجاه اللغة الأساسية أساس (MANDATORY)

الخصائص المنطقية (`margin-inline-start`) بدل الاتجاهية (`margin-left`). الافتراضي في الإطار: RTL.

### CS-051 — النماذج متعددة الخطوات: لا «السابق» في الأولى، ولا انتقال قبل التحقق (MANDATORY)

يسري على كل نموذج إدخالٍ مقسَّمٍ على أكثر من خطوة أو تبويب (معالج `Wizard`)، في كل واجهات المنصة:

1. **لا يظهر «السابق»/«رجوع» في الخطوة الأولى.** يجوز أن يقوم مقامَه «إلغاء» إن كانت الشاشة تحمله.
2. **«التالي» مُفعَّلٌ دائمًا ولا يُعطَّل صامتًا.** الضغطُ عليه يتحقق من حقول **الخطوة الحالية وحدها** وفق قواعد النموذج المحددة سلفًا (الإلزام · الطول · الصيغة · المدى · العلاقة بين الحقول). عند أيّ خطأ يبقى المستخدم في الخطوة، وتظهر رسالةُ كل حقلٍ تحته — **نصُّ مواصفة الشاشة إن عرّفته** — ويُنقل التركيز إلى أول حقلٍ خاطئ. ولا ينتقل إلا والخطوةُ صحيحة.
3. **الإرسال النهائي يتحقق من كل الخطوات،** فإن كان الخطأ في خطوةٍ سابقة عاد إليها وأظهر رسائلها.
4. **الرجوع لا يتحقق،** والرسالةُ تزول حين يُصحَّح حقلُها.
5. **الخادم يبقى المرجع:** تحقق الواجهة تيسيرٌ للمستخدم لا بديلٌ عن تحقق الخادم، وأخطاءُ الخادم (`422`) تُعاد إلى خطوة حقلها.
6. **الأداة المشتركة:** `useStepGate` في `frontend/src/shared/components/wizard/` تحمل هذا السلوك، والشاشةُ تقدّم دالةَ تحقق الخطوة (`CS-043`: المكوّن يعرض والخطّاف يدير). لا يُكتب انتقالُ خطواتٍ يدويٌّ جديد خارجها.

المخالفةُ تُرفض في المراجعة: زرُّ «التالي» المعطَّل بلا رسالة، أو «السابق» في الخطوة الأولى، أو انتقالٌ بلا تحقق.

### CS-052 — النص المعروض ليس بيانات (MANDATORY)

لا يُبنى قرار في الكود على نصٍّ معروض أو جزء منه (`message.includes('مهلة')` · قائمة تسميات تحدد الحقول المعروضة). القرار على **كود** (`ERR-*` · `enum` · علم من الخادم). النص يتغيّر بالترجمة وبالصياغة وبقرار المالك، فينهار ما بُني عليه بصمت. الاستثناء الوحيد المُعلَن: ما يكتبه المستخدم بنفسه (كلمات الموافقة)، وهو بيانات بطبيعته. (`internationalization-standard.md` — `I18N-001`.)

### CS-053 — لا رمز تقني في رسالة للمستخدم (MANDATORY)

تسمية الحالة في رسالة من `label()` في الـ`enum` لا من قيمتها الخام («حالته الآن جارٍ» لا «حالته الآن ACTIVE»)؛ والرسالة التي تحمل قيمة متغيّرة قالبٌ بموضع محجوز لا ضمٌّ. يسري على الخادم والواجهة. المخالفة في المرجع كشفتها جولة الفحص الشامل لا المراجعة.

### CS-054 — أسماء حقول التحقق مترجمة (MANDATORY)

كل حقل يظهر في رسالة تحقق (`422`) له اسم في `validation.attributes` بكل لغة تعرضها المنصة («حقل الإقرار مطلوب» لا «حقل acknowledged مطلوب»). الحقل الجديد بلا اسم مترجم يُرفض في المراجعة.

## 4. الاختبارات

### CS-060 — الاختبار يوثّق سيناريوهه (MANDATORY)

`RS-041`: `@scenario TS-ORD-001` في التوثيق البرمجي.

### CS-061 — بنية AAA (MANDATORY)

Arrange · Act · Assert — مفصولة بصريًا.

### CS-062 — لا اعتماد على ترتيب التنفيذ (MANDATORY)

كل اختبار مستقل ويعمل منفردًا. قاعدة البيانات تُهيّأ وتُنظَّف لكل اختبار.

### CS-063 — تغطية المسار الاستثنائي إلزامية (MANDATORY)

`TST-*`: اختبار المسار السعيد وحده **لا يُعدّ تغطية**. كل `BR-*` حرجة تحتاج اختبار رفض أيضًا.

## 6. آليات الفرض

| الأداة | الغرض | الحالة |
|---|---|---|
| **Pint** | PSR-12 + التنسيق | مُفعَّل — مرحلة `stage_fmt` |

### 7.1 `CS-OD-02` — لماذا 8 لا 9

القرار **بالقياس لا بالتفضيل**. يُشغَّل level 8 على الشريحة التأسيسية وتُعالَج ملاحظاته كلها حتى الصفر قبل تفعيل البوابة؛ وأصناف الملاحظات المتوقعة:

| النوع | الحكم |
|---|---|
| `property.notFound` | خصائص Eloquent السحرية — **نقص توثيق** يُعالَج بإضافة `@property` للنماذج |
| `argument.type` · `offsetAccess` | **عيوب حقيقية** في التأكيدات — تُعالَج |
| `nullsafe.neverNull` | `?->` على قيمة غير قابلة للعدم — تُعالَج |
| `class.notFound` · `generics` | **بقايا حقيقية** (مثل مصنع يشير إلى صنف محذوف) — تُحذف |

**النتيجة المطلوبة: صفر ملاحظة عند level 8.**

**لماذا لا 9:** المستوى 9 يفرض `mixed` صارمًا، وأثره الأكبر على حدود إطار العمل (حمولات الطلب والاستجابة) حيث يُنتج ضجيجًا يُعالَج بـ`@phpstan-ignore` لا بتحسين فعلي. الفارق بين 8 و9 هنا **إخفاء لا كشف**. يُعاد النظر عند اكتمال الواجهة.

**الفائدة المُثبَتة في المشروع الأصل:** الملاحظات لم تكن شكلية — كشفت مصنع بيانات يشير إلى نموذج **محذوف**، وهو خطأ كان سينفجر عند أول استخدام للمصنع.
