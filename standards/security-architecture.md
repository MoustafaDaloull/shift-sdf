# Security Architecture — معيار البنية الأمنية

> يُحدد هذا المعيار الضوابط الأمنية الشاملة: حماية البيانات، أمن الاتصالات، إدارة الأسرار، أمن التكاملات، فصل البيئات، والاستجابة للحوادث.
>
> يبني على `EP-SEC-001..004` و`EP-INT-001..004`. يجمع ويُفصِّل الضوابط المتفرقة في `architecture.md` (ملكية الأصول · ضوابط الأمن · الخصوصية).
>
> القواعد المرتبطة بحزمة تقنية بعينها تُطبَّق عبر ملف تعريف الحزمة `profiles/<name>/`؛ الافتراضي `laravel-react`.

## 2. حماية البيانات

### SEC-001 — تصنيف البيانات

**التصنيف:** `MANDATORY`

جميع البيانات مُصنفة حسب `DD-008` (5 مستويات: عادي، شخصي، حساس، مالي، نظامي). الضوابط الأمنية تُطبق حسب المستوى.

### SEC-002 — التشفير في التخزين

**التصنيف:** `MANDATORY`

| نوع البيانات | الضابط |
|---|---|
| كلمات المرور | تشفير أحادي الاتجاه (`AUTH-007`) |
| أسرار النظام (API Keys, Tokens) | Secret Manager (`EP-INT-001`) |
| بيانات قاعدة البيانات | تشفير على مستوى التخزين (Encryption at Rest) — يوفره المحرك المُدار |
| الملفات في Object Storage | تشفير على مستوى التخزين — يوفره مزود Object Storage المعتمد |

### SEC-003 — التشفير في النقل

**التصنيف:** `MANDATORY`

- جميع الاتصالات الخارجية عبر HTTPS/TLS (`architecture.md`).
- الاتصالات الداخلية بين الخدمات عبر HTTPS أو شبكة خاصة مُدارة.
- لا نقل بيانات بدون تشفير.

### SEC-004 — إخفاء البيانات الشخصية

**التصنيف:** `MANDATORY`

- البيانات الشخصية لأصحاب السجلات لا تظهر للعامة (`EP-SEC-003`، `business-rules-global.md`).
- المعرّفات الرسمية الحساسة للسجل تظهر فقط للمالك والإدارة.
- الوثائق الشخصية تُوصل عبر Signed URLs (`architecture.md`).
- تفاصيل Audit Log لا تظهر للمستخدمين العاديين.

### SEC-005 — بيانات الدفع

**التصنيف:** `MANDATORY`

- لا تُخزن بيانات البطاقة الائتمانية داخل المنصة.
- بوابة الدفع المعتمدة تُدير بيانات البطاقة.
- المنصة تحتفظ فقط بمعرّف العملية والنتيجة.

## 3. إدارة الأسرار

### SEC-006 — Secret Manager

**التصنيف:** `MANDATORY`

جميع الأسرار تُحفظ في خدمة إدارة أسرار مُدارة (`EP-INT-001`):

- مفاتيح بوابة الدفع.
- مفاتيح SMS Provider.
- مفاتيح Email Provider.
- أسرار قنوات المراسلة.
- مفاتيح AI Service.
- أي مفتاح أو كلمة مرور لتكامل خارجي.

### SEC-007 — منع الأسرار في الكود

**التصنيف:** `PROHIBITED`

- لا تُحفظ أسرار في الكود المصدري.
- لا تُحفظ في ملفات التكوين غير المشفرة.
- لا تُحفظ في متغيرات البيئة غير المحمية.
- لا تُسجل في سجلات التطبيق أو Audit Log.
- لا تظهر في استجابات API (`ECS-019`).

### SEC-008 — فصل الأسرار بين البيئات

**التصنيف:** `MANDATORY`

أسرار التطوير والاختبار والإنتاج مفصولة تمامًا (`architecture.md`). لا يُستخدم مفتاح إنتاج في بيئة اختبار أو العكس.

## 4. أمن التكاملات الخارجية

### SEC-009 — مبادئ التكامل الآمن

**التصنيف:** `MANDATORY`

كل تكامل خارجي يحقق (`EP-INT-001..004`):

1. الأسرار في Secret Manager (`SEC-006`).
2. لا حسابات شخصية في الإنتاج.
3. HTTPS إلزامي.
4. Retry مع Backoff للعمليات الحرجة.
5. Webhooks مُسجلة ومتحقق من صحتها.

### SEC-010 — التحقق من Webhooks

**التصنيف:** `MANDATORY`

Webhooks الواردة (خصوصًا من بوابة الدفع) يجب:

1. التحقق من التوقيع (Signature Verification) إن وفره المزود.
2. التحقق من مصدر IP إن أمكن.
3. معالجة idempotent (`EVT-010`، `DMOD-030`).
4. تسجيل في سجلات المراقبة.

### SEC-011 — ملكية الأصول

**التصنيف:** `MANDATORY`

جميع أصول المشروع (Cloud، Domain، قواعد البيانات، بوابات الدفع) باسم العميل (`architecture.md`). صلاحيات مزود التطوير بالحد الأدنى ومُوثقة.

## 5. فصل البيئات

### SEC-012 — البيئات المطلوبة

**التصنيف:** `MANDATORY`

| البيئة | الغرض |
|---|---|
| Development | التطوير المحلي |
| Staging | الاختبار قبل الإنتاج |
| Production | التشغيل الفعلي |

### SEC-013 — قواعد الفصل

**التصنيف:** `MANDATORY`

- لا بيانات إنتاج في بيئات التطوير أو الاختبار.
- بيانات الاختبار مُولَّدة وليست حقيقية (`EP-SEC-004`، `DD-009`).
- أسرار مفصولة (`SEC-008`).
- قاعدة بيانات مفصولة لكل بيئة.

## 6. أمن التطبيق

### SEC-014 — OWASP Top 10

**التصنيف:** `MANDATORY`

يُراعى الحماية من ثغرات OWASP Top 10:

| الثغرة | الضابط |
|---|---|
| Injection | Parameterized Queries / ORM |
| Broken Authentication | `authentication-standard.md` |
| Sensitive Data Exposure | `SEC-004`, `DD-008..009` |
| Broken Access Control | `authorization-standard.md` |
| Security Misconfiguration | فصل البيئات + مراجعة الإعدادات |
| XSS | تنظيف المدخلات + ترميز المخرجات |
| CSRF | Token-based protection |

### SEC-015 — تنظيف المدخلات

**التصنيف:** `MANDATORY`

جميع المدخلات من المستخدم تُنظف وتُتحقق قبل المعالجة:

- التحقق من النوع والطول والصيغة.
- **تحقّقٌ مُقيَّد عند الإدخال:** الحقول التي لا تحتمل `<` أو `>` أصلًا — الأسماء · الهاتف · البريد · الأكواد · المعرّفات — **ترفض** المدخل الحامل لأيٍّ منهما برسالة التحقق العادية للموديول؛ لا إزالة ولا ترميز عند الإدخال.
- **ترميزٌ إلزاميٌّ عند كل مخرَج:** النصّ الحرّ يُخزَّن كما أُدخل ويُرمَّز عند كل حدّ إخراج (React افتراضيًّا؛ وصراحةً في البريد وPDF وCSV والرسائل النصية)، ولا `dangerouslySetInnerHTML` بلا قرار مستقل لكل موضع.
- لا يُثق بأي مدخل من العميل دون تحقق خادمي.

## 7. المراقبة الأمنية

### SEC-016 — الأحداث المُراقبة

**التصنيف:** `MANDATORY`

يُراقب ويُنبه عند:

- محاولات مصادقة فاشلة متكررة.
- محاولات وصول غير مصرح.
- تجاوز Rate Limit.
- فشل التحقق من Webhook.
- أخطاء نظام متكررة.
- تغييرات في صلاحيات المستخدمين الإداريين.

### SEC-017 — الاستجابة الأمنية

**التصنيف:** `MANDATORY`

عند اكتشاف حادث أمني:

1. تسجيل الحادث مع التفاصيل.
2. إبلاغ الفريق المسؤول.
3. عزل المكون المتأثر إن أمكن.
4. التحقيق وتحديد السبب.
5. إصلاح الثغرة.
6. توثيق الحادث والإجراءات المتخذة.
